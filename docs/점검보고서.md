## 1. 위험한 데
- **로그아웃 뒤 빈 내용 올리기 (추정)** — app.js:211-223 `logout()` 은 `state.tagDb = new Map()`, `state.libFileId = null`, `state.playlists = []`, `state.plFileId = null` 으로 비우지만 `state.libSaveTimer`·`state.plSaveTimer`·`libDirty`·`plDirty` 는 그대로 둔다. 고친 지 1.2초 안에, 또는 태그 읽는 중·저장 재시도 중에 로그아웃하면 `flushLibrary()`/`flushPlaylists()` 가 빈 목록을 `uploadMd(null, …)` 로 보내 **새 빈 파일**을 만들려 한다 (토큰이 없으니 로그인 창을 다시 띄우려 할 수도 있음). 게다가 로그아웃이 이 기기 복사본(`dm:library`)도 지워서, 아직 못 올린 고친 태그는 사라진다. → `logout()` 맨 앞에서 두 타이머를 `clearTimeout` 하고 dirty 를 false 로, 또는 올리기를 먼저 끝낸 뒤 로그아웃.
- **같은 이름 파일이 둘 생김** — app.js:1330-1350 `loadTagDb()` 가 드라이브 읽기에 실패하면 경고만 남기고 `libFileId` 를 null 로 둔 채 끝난다. 그런데 `openFolder()`(app.js:402-410)는 이어서 `scanTags()` 를 돌리고, 25곡마다 `flushLibrary()` → `uploadMd(null, …)` 가 `drive-music-library.md` 를 **새로** 만든다. 새 기기라면 이 새 파일엔 앱에서 고친(edited) 값이 없다. 플레이리스트도 같음: `loadPlaylists()`(app.js:1239-1256)가 실패하면 `plFileId` 가 null 이라 다음 저장 때 새 파일. → 읽기에 실패했으면 "읽기 실패" 표시를 두고 그동안은 새로 만들지 말기(올리기 보류). 찾을 때 `orderBy: "modifiedTime desc"` 도 넣기.
- `loadPlaylists()` 는 드라이브 것으로 이 기기 복사본을 그냥 덮는다 (app.js:1250-1251) — 지난번에 못 올린 변경이 있었다면 사라짐. 급하진 않음.
- 하드코딩 경로·비밀값: 없음 (`config.js:8` 클라이언트 ID 는 위 "그냥 알아 둘 것" 참고).
